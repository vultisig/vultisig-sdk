`RujiraWithdraw` no longer hardcodes `chainId: 'thorchain-1'` in the withdrawal keysign payload's `prepareSignDirectTx` metadata-harvest call. It now reads the signer's actual configured chain ID (`VultisigRujiraProvider.getChainId()`, already exposed but previously unused here) when available, falling back to mainnet for backward compatibility. A `VultisigRujiraProvider` constructed for a non-default chain ID (e.g. a testnet) no longer silently drifts to mainnet on the withdrawal path.
