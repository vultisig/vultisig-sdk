`buildCctpClaim` now decodes the CCTP message (`decodeCctpBurnMessage`) and cross-checks the burn's source domain, destination domain, sender/recipient TokenMessenger, and burned token against the stated `sourceChain`/`destinationChain` before encoding `receiveMessage` calldata, and refuses to build a claim whose mint recipient is a known burn/dead address — ported from `agent-backend-ts`'s `build_cctp_claim_usdc` handler so the SDK builder no longer treats the message as opaque bytes. `BuildCctpClaimParams` gains a required `sourceChain` field and `CctpClaimResult` gains a `burn` field exposing the decoded, cross-checked burn identity.
