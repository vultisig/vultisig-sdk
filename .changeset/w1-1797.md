Deduplicated the cosmos validator/account bech32 role guard (fund-safety: rejecting a `valoper`/`valcons` address where a spendable account is required). `ibcTransfer.ts` and `cosmosStaking.ts` each carried their own private reimplementation of the HRP-suffix classification alongside the canonical one in `tools/swap/skip/cosmosAddressGuard.ts`; both now import and consume the shared `validatorRoleForHrp` helper instead, so the fund-safety rule can no longer drift silently across call sites.
