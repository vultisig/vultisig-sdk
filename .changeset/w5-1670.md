StakeKit's canonical yield scan surface used to be singular (`buildYieldActionScanRequest` returned only the first scannable step) and EVM-only, so multi-step yield actions couldn't hand every leg to a downstream scanner and non-EVM (Solana) steps fell back to a generic `unsupported: chain_not_supported` sentinel. Added `buildYieldActionScanRequests` (plural), returning one `ScanRequest` per `transactions[]` step 1:1, and a new `SolanaScanRequest` kind so Solana yield steps (which ship pre-built tx bytes directly in `unsignedTransaction`, same as the SDK's existing `canonicalizeSolanaStep` extraction) get a real scan request instead of the unsupported fallback. `stakekitBuildEnter`/`stakekitBuildExit`/`stakekitBuildManage` now attach both `scan_request` (singular, unchanged for backward compatibility) and `scan_requests` (plural, all steps) to their response envelopes. `buildYieldActionScanRequest` (singular) keeps its exact prior behavior.
