`SwapQuoteParams`, `SwapTxParams`, and `VaultBase.swap()` now accept an `amountBaseUnits: bigint` alternative to the existing human-readable `amount`, mutually exclusive with it. A consumer that already holds an authoritative base-units amount (for example rehydrating a swap from a backend tx envelope) can now call `getSwapQuote`/`prepareSwapTx`/`swap` directly with that bigint instead of reconstructing a decimal string first — the SDK owns the scaling policy end-to-end. `vultisig-cli`'s THOR/Maya `MsgDeposit` swap dispatch and local Solana swap build path have been migrated onto `amountBaseUnits`, removing their local base-unit-to-decimal reconstruction.
