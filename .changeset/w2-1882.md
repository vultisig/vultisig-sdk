The SDK already computed the canonical signing-algorithm (ECDSA vs EdDSA vs mldsa) decision per chain internally (`@vultisig/core-chain/signing/SignatureAlgorithm`), but never exposed it on the public `@vultisig/sdk` surface. First-party consumers (agent-backend's swap/get-address/get-receive-info tools) were re-declaring local EdDSA chain sets to make the same decision. `getSignatureAlgorithm` and `signatureAlgorithms` are now re-exported from the SDK root so consumers can import one canonical seam instead of duplicating the mapping.
