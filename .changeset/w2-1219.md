`searchToken()` only modeled token discovery as CoinGecko "platform deployments" (contract addresses), so curated XRPL issued currencies like RLUSD — already known internally via `knownTokens[Chain.Ripple]` — were invisible on the public search surface, since CoinGecko doesn't list XRPL tokens with a `ripple` contract-address platform entry. Overlaid the curated `knownTokens[Chain.Ripple]` entries onto their matching CoinGecko coin (keyed by `priceProviderId`, the CoinGecko coin id each curated entry already carries), so `searchToken('RLUSD')` now surfaces a `Ripple` deployment alongside any contract deployments CoinGecko already reports. `TokenDeployment.contractAddress` is documented as the chain's canonical token identifier (contract address, SPL mint, Sui coin type, or — for XRPL — the `<currency>.<issuer>` composite id), not strictly an EVM contract.
