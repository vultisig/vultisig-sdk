Add `assertCctpMintSideHasCode(destinationChain)`, a runtime fail-closed guard that verifies a CCTP destination chain's MessageTransmitter contract actually has deployed code before a burn tx is surfaced for signing. The existing CI oracle test pins the registry against Circle's published addresses, but only catches drift that goes through CI — this guards the next drift (a wrong chain entry, a Circle redeploy) at the moment a route is actually built, so a burn is refused rather than sent with no verified mint path. Fail-closed only (a false negative just blocks the route temporarily, never signs or broadcasts); positive results are cached per (chain, address) for the process lifetime to avoid per-quote RPC spam, and negatives are never cached.
